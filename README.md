# Финансовый ассистент

Интеллектуальный ассистент для анализа и прогнозирования личных финансов: учёт доходов и
расходов, импорт операций из файла, автоматическая категоризация, аналитика с графиками,
поиск повторяющихся платежей, прогноз расходов методами машинного обучения и рекомендации
по планированию бюджета.

## Технологии

| Слой | Технология |
|---|---|
| Веб-фреймворк | FastAPI, Uvicorn |
| Интерфейс | Jinja2, Bootstrap 5, Chart.js (локально, без CDN) |
| База данных | SQLAlchemy 2.0, Alembic, SQLite (с возможностью перехода на PostgreSQL) |
| Анализ и ML | pandas, scikit-learn, statsmodels |
| Курсы валют | API Национального банка Республики Беларусь |
| Качество кода | pytest, ruff |

## Структура проекта

```
  config.py        настройки (переменные окружения, .env)

  cli.py           консольные команды (python -m app.cli --help)
  models/          ORM-модели (таблицы БД)

  labels.py        русские названия значений перечислений
  schemas/         Pydantic-схемы: проверка входных данных, формат ответов API
  services/        бизнес-логика
  integrations/    клиенты внешних сервисов (курсы НБРБ, ЦБ РФ, currency-api)
  importers/       разбор файлов с операциями (CSV; расширяемо под другие форматы)
  ml/              статистические компоненты (классификатор описаний операций)
  utils/           вспомогательные функции
  api/             REST API (JSON), документация на /docs
  web/             HTML-страницы
  templates/       шаблоны Jinja2
  static/          CSS, JS, сторонние библиотеки (vendor/)
migrations/        миграции схемы БД (Alembic)
data/              файл БД и прочие данные времени выполнения (не хранится в git)

```

## Установка и запуск (Windows, PowerShell)

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
Copy-Item .env.example .env        # при необходимости отредактировать
.\.venv\Scripts\python.exe -m app.cli init-db   # миграции + стартовые категории
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

После запуска:

- веб-интерфейс: <http://127.0.0.1:8000>
- документация API (Swagger): <http://127.0.0.1:8000/docs>

## Проверка кода

```powershell

.\.venv\Scripts\python.exe -m ruff check .      # линтер
```

## Переход на PostgreSQL

Установить драйвер (`pip install "psycopg[binary]"`), указать в `.env`
`DATABASE_URL=postgresql+psycopg://user:password@localhost:5432/finance`
и выполнить `python -m app.cli init-db`. Код приложения менять не нужно.

## Импорт операций из файла

Страница **«Импорт»**: загрузка файла → предпросмотр (новые / уже загруженные / ошибки) →
подтверждение. Шаблон CSV можно скачать на странице импорта.

- Обязательные столбцы: дата и сумма; необязательные: тип, валюта, описание, категория.
  Названия столбцов — на русском или английском, в любом порядке.
- Кодировка UTF-8 или Windows-1251, разделитель `;`, `,` или табуляция.
- Повторно загруженные операции распознаются по «отпечатку» строки и не дублируются.
- Новые форматы (Excel, выписки банков) добавляются отдельным классом в `app/importers/`.

Пример файла: `data/samples/sample_import.csv`.

## Демо-данные

```powershell
.\.venv\Scripts\python.exe -m app.cli demo-data            # CSV за 12 месяцев → data/samples/
.\.venv\Scripts\python.exe -m app.cli demo-data --load     # сгенерировать и импортировать в БД
.\.venv\Scripts\python.exe -m app.cli demo-data --help     # все параметры
```

Генератор воспроизводим (параметр `--seed`) и создаёт размеченную выборку: у каждой операции
есть истинная категория, которая используется для оценки качества категоризации.

## Аналитика

Страница **«Аналитика»** (и `GET /api/analytics`) за выбранный период — этот/прошлый месяц,
3/6/12 месяцев, с начала года, всё время или свои даты:

- сводка: доходы, расходы, баланс, доля сбережений, средний расход в день;
- сравнение с предыдущим периодом той же длины (общие суммы и каждая категория);
- структура расходов (кольцевая диаграмма) и доходов по категориям;
- динамика доходов, расходов и баланса по дням / неделям / месяцам (выбирается по длине
  периода автоматически или вручную), пустые интервалы заполняются нулями;
- наиболее затратные категории и крупнейшие операции.

Все суммы — в BYN (`amount_byn`).

## Регулярные платежи

Страница **«Регулярные»** (и `GET /api/recurring?months=12`) находит подписки, связь, ЖКУ,
зарплату и другие повторяющиеся операции:

1. операции за окно анализа группируются по типу, валюте и описанию без цифр и знаков;
2. группа из ≥ 3 операций периодична, если медианный интервал соответствует неделе (7 ± 2),
   месяцу (30 ± 4), кварталу (91 ± 10) или году (365 ± 20) и ≥ 75 % интервалов в допуске;
3. сумма стабильна: коэффициент вариации ≤ 35 % (≤ 5 % — фиксированная сумма);
4. следующая дата = последняя + период; просроченный сверх допуска платёж считается
   прекращённым.

Показываются ближайшие платежи на 30 дней, стоимость регулярных расходов в месяц и их доля
в среднемесячных расходах.

## Прогноз расходов

Страница **«Прогноз»** (и `GET /api/forecast?granularity=month&horizon=3`): по месяцам
(горизонт 1–6) или по неделям (1–12).

- Ряд строится по полным периодам; текущий (незавершённый) период — первый прогнозируемый,
  рядом показано, сколько в нём уже потрачено. Пустые периоды внутри истории = 0; периоды
  без данных в конце истории считаются невнесёнными, и прогноз начинается после них.
- Модели: скользящее среднее (3), линейная регрессия по времени, сглаживание Хольта
  с затухающим трендом.
- Выбор модели — скользящий бэктест на последних 4 месяцах / 8 неделях: каждая модель
  предсказывает период на шаг вперёд, обучаясь только на предыдущих данных; побеждает
  минимальная MAE (при равенстве — более простая модель). Также считается MAPE.
- Интервал ≈ 80 %: ±1,28 · σ ошибок бэктеста · √шага.
- Отдельно прогнозируются крупнейшие категории (каждая со своей лучшей моделью).

```powershell
.\.venv\Scripts\python.exe -m app.cli forecast [--granularity week] [--horizon N]
```

## Гибридная категоризация

Категория операции, не выбранная пользователем вручную, определяется каскадом:

1. **База знаний** (символьный компонент) — ключевые слова категорий (страница «Категории»);
   слово совпадает только целиком, без учёта регистра и «ё», среди категорий того же типа.
2. **ML-модель** (статистический компонент) — TF-IDF по символьным n-граммам (2–5) +
   логистическая регрессия; возвращает категорию и вероятность.
3. **Арбитр** сравнивает результаты:

| Ситуация | Решение | Проверка |
|---|---|---|
| Правило и модель совпали | категория правила | — |
| Сработали правила нескольких категорий | кандидат, выбранный моделью | — |
| Правило и уверенная модель (≥ 80 %) разошлись | категория правила (приоритет базы знаний) | нужна |
| Только правило / модель не уверена | категория правила | — |
| Правил нет, модель уверена (≥ 60 %) | категория модели | — |
| Правил нет, модель не уверена или не обучена | «Прочие расходы / доходы» | нужна |

У каждой операции сохраняется пошаговый протокол решения (`categorization_trace`), он показан
в карточке операции. Ручные категории никогда не перезаписываются автоматически; исправление
пользователя становится обучающим примером. Модель обучается на ручных категориях и бесспорных
решениях правил (собственные предсказания модели в обучение не попадают).

```powershell
.\.venv\Scripts\python.exe -m app.cli train-categorizer      # обучить модель
.\.venv\Scripts\python.exe -m app.cli recategorize           # пересчитать автоматические категории
.\.venv\Scripts\python.exe -m app.cli evaluate-categorizer   # сравнить правила / ML / гибрид
```

Оценка проводится на операциях с ручными категориями в двух сценариях: случайное разбиение
70/30 и «новые описания» (описания тестовой части не встречаются в обучающей). Метрики:
точность, покрытие (доля операций с категорией не «Прочие»), точность на покрытых, macro-F1,
время на операцию.

## Курсы валют

Операции в USD пересчитываются в BYN по курсу на дату операции. Порядок получения курса:

1. Кэш — курс, уже полученный ранее на эту дату (таблица `exchange_rates`).
2. Онлайн-источники по очереди: **НБРБ** → **ЦБ РФ** (кросс-курс USD/RUB ÷ BYN/RUB) →
   **currency-api** (рыночный курс, два зеркала).
3. Если все источники недоступны (нет интернета), пользователь выбирает:
   ввести курс вручную или взять курс из истории системы — ближайший известный курс
   (из кэша или прошлых USD-операций) не дальше `RATE_HISTORY_MAX_DAYS` дней (по умолчанию 7).

Источник курса сохраняется в каждой операции (`rate_source`).

## Модель данных

| Таблица | Назначение |
|---|---|
| `categories` | Категории доходов и расходов (название, тип, цвет, признак системной) |
| `category_rules` | Ключевые слова для автоматической категоризации |
| `transactions` | Операции: дата, тип, сумма, валюта, курс, сумма в BYN, описание, категория |
| `exchange_rates` | Кэш курсов НБРБ (BYN за 1 единицу валюты на дату) |

Суммы хранятся в `Numeric(12, 2)` (точная десятичная арифметика), сумма операции всегда
положительна, направление определяется типом. Вся аналитика считается в BYN по полю
`amount_byn`.
